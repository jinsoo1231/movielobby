AI 웹 개발 헌법

제1조 (기술 부채 방지와 문서화)

1. AI를 통해 빠르게 구현한 기능은 완성 직후 "이 코드를 더 효율적으로 최적화할 방법이 있을까?"라고 물어 품질을 개선한다.
2. 나중에 코드를 다시 봤을 때 헷갈리지 않도록, 복잡한 로직에는 반드시 한글 주석을 달아준다.

제2조 (기존 코드 보존 및 임의 수정 금지의 원칙)

1. 기능 업데이트나 에러 수정 시, 해당 작업과 직접적으로 관련된 부분을 제외한 나머지 기존 소스 코드는 어떠한 경우에도 임의로 삭제, 축약, 또는 변경하지 않는다.
2. AI는 코드를 수정 및 적용할 때, 기존에 정상 작동하던 전체 구조와 로직을 100% 그대로 유지한 상태에서 변경점만 안전하게 반영해야 한다.

제3조 (최신 단일 백업 유지의 원칙)

1. 만일의 사태를 대비하여, 코드를 수정하기 직전에는 가장 최근에 에러 없이 정상 작동했던 상태를 딱 1개의 백업 파일(예: page_backup.tsx)로 복사해 둔다.
2. 새로운 백업을 만들 때는 기존 백업 파일에 계속 덮어쓰기하여, 항상 '직전의 가장 안전한 상태' 하나만 유지되도록 관리한다.

제4조 (코드 수정 및 배포 워크플로우 준수의 원칙)

1. 코드 수정 완료 안내: AI는 코드를 수정한 직후 즉시 깃허브 커밋을 시도하지 않고, 우선 사용자에게 코드 수정이 완료되었음을 안내한다.
2. 사용자 검토 및 로컬 테스트: 사용자가 에디터에서 변경 사항을 수락(Accept All)하고 로컬 서버에서 에러가 없는지 직접 확인할 때까지 대기한다.
3. 커밋 및 푸시 진행: 사용자의 정상 작동 확인이 끝난 이후에만 깃허브 커밋(git commit) 명령어를 안내하거나 진행한다.

제5조 (UI 가시성 및 심플한 디자인 유지의 원칙)

1. 모든 UI 구성요소는 바탕색과 글자색(또는 아이콘 색상)이 겹쳐서 보이지 않는 문제가 발생하지 않도록, 명확한 대비(Contrast)를 유지하여 디자인한다. (예: 밝은 배경에는 어두운 글씨, 어두운 배경에는 밝은 글씨 적용)
2. 과도하게 복잡한 디자인 보다는 직관적이고 심플한 모던 디자인을 지향한다.
